# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Marketing site for Glow Wild (glowilds.com), built with Hugo on the vendored Hugo Hero theme (`themes/hugo-hero-theme`). There is no JS build, package manager or test suite.

## Commands

- `hugo server`: local dev at http://localhost:1313. In server mode the CSS is linked with source maps; in production builds it's inlined.
- `hugo --minify`: production build, the same command CI runs. A clean build with no `ERROR` lines is the only automated check.
- `hugo --minify -d <tmpdir>`: build somewhere else for inspection. `public/` is gitignored and often stale; old dev builds there contain `localhost` URLs.
- Requires Hugo **extended**, 0.158 or newer, and Dart Sass (`sass` on PATH). CI pins `HUGO_VERSION` and `DART_SASS_VERSION` in `.github/workflows/hugo.yml`. Hugo caches compiled CSS in `resources/_gen`, so set `HUGO_RESOURCEDIR=<empty tmpdir>` when you need to prove the Sass step really runs.

## Deploy

Pushing to `main` builds the site and publishes it to GitHub Pages (the custom domain is glowilds.com). Check with `gh run list` / `gh run watch`. There is no staging environment.

## Architecture

- **Theme overrides:** files under `layouts/` shadow the same path in `themes/hugo-hero-theme/layouts/`. To change a theme template, copy it into `layouts/` and edit the copy; never edit the theme. The theme copies only exist where something was changed.
- **Headless bundles:** homepage sections come from `content/homepage/*.md`, and the About and How It Works page sections from `content/pages/{about,process}/content*.md`. They are ordered by `weight`, with a `background`, `button` and `buttonLink` in front matter, and rendered as "strips" by `layouts/index.html` and `layouts/pages/about.html`. Both pages use `layout: 'about'`. Optional `phoneBackground` (About and How It Works strips): a 2:1 picture that phones show whole above the text; setting it also makes desktop fit `background` whole and left-aligned instead of covering the strip. Use it for composed graphics, not photos. The strip markup is shared in `layouts/partials/strip.html`; the Who We Help list (`layouts/work/list.html`) uses it too, one strip per industry with its summary (text above `<!--more-->`) and the same `background`, `phoneBackground` and `align` front matter. The How It Works and Who We Help pictures (`static/images/process-*.svg`, `static/images/work-*.svg`), the page banners (`static/images/hero-*.svg` plus `.jpg` copies for link previews, made with ImageMagick) are neon line drawings generated by `python3 design/drawings.py` (except the About banner: the founder photo, built by `python3 design/about_banner.py` from `Photo/`, which is not in git; it also writes `static/images/founder.jpg`, the founder's square photo used only in the About JSON-LD); edit the script and rerun it rather than editing the SVGs, and rerun it after changing a step's or industry's `align` (it reads `align` to put the drawing on the other side). On desktop the picture sits opposite the text: the strip gets an `align-<left|right>` class from its `align`.
- **Collections:** `content/services/` and `content/work/` (the "Who We Help" industries). Services marked `featured: true` show on the homepage in "One Connected System" (`id="pricing"`, where `/#pricing` links land): one card each, filled with its WILD color and glowing, with its `pillar` label (Visibility, Intelligence, Automation, Improvement) and `heroSubHeading`, then one line with the starting prices from `data/pricing.yaml`. The Services page (`layouts/services/list.html`) lists each with its first paragraph, then the `_index.md` body. Service and industry pages end with a block from `section-single.html`: the towns, on service pages the starting prices and links to the industries, on industry pages links to the services. A service's prices come from `layouts/partials/service-prices.html` (site-wide numbers unless its front matter sets `pricing: {setup: N, monthly: N}`, 0 = none), used by both the page and its JSON-LD offers. Each page sets `heroHeading`, `heroSubHeading` and `heroBackground`. Their single pages share `layouts/_default/section-single.html`, picked by a `cascade` in each section's `_index.md`. Industry pages set a short `linkTitle` for the footer links. Cards take a WILD color from `weight`: 1 green, 2 pink, 3 blue, 4 purple.
- **Site-wide data:** `data/contact.yaml` (email, phone, `formAction`, `owner`, `legalName`, `googleProfile` (added with the social links as `sameAs` in the homepage JSON-LD), address, `city`/`region` for the structured data, `areaServed` towns, hours), `data/testimonials.yaml`, and `data/pricing.yaml` (site-wide starting prices, `setupFrom` and `monthlyFrom`, shown on the homepage and in `/llms.txt`; the FAQ fills them in through `{setupFrom}` / `{monthlyFrom}` placeholders, like `{towns}`, instead of typed numbers). Templates hide a block while its value is empty: the phone, the contact form and the testimonials section all stay hidden until filled. Keep that pattern for new optional content. Testimonials must be real quotes.
- **Booking button:** `layouts/partials/cta.html`, called as `{{ partial "cta.html" "<spacing class>" }}` from the homepage hero and the service and industry pages; banner pages get it with `"cta" true` in the `hero-image-setheight.html` dict (About, Who We Help). The contact form's submit button has its own copy of the label. `assets/js/scripts.js` sends the form to Formspree in the background and shows a thank-you line; on any failure it posts the form normally, so a request is never lost. Check it with `python3 design/contact_form_check.py` (Playwright, against `hugo server`; sends nothing to Formspree).
- **Meta and SEO:** `layouts/partials/seo.html` adds the canonical link, homepage-only business JSON-LD built from `data/contact.yaml`, on service and industry pages a breadcrumb trail plus a `Service` block with the same towns (industry pages add the industry as `audience`; service pages add `offers` from `layouts/partials/service-prices.html`, the same numbers the page shows), and on /about/ an `AboutPage` with the founder (`owner`) as a Person. The blocks link by `@id`: the business is `<baseURL>#business`, the founder `<baseURL>about/#founder`. Opening hours go into that JSON-LD only when written like `8:00am`; other values are skipped. `/llms.txt` (a plain-text summary for AI assistants) is built from `layouts/home.llms.txt`. Every page, the homepage included, gets its `<meta>` tags from `layouts/partials/meta-default.html`; the homepage's description and `seoTitle` are in `content/_index.md`.
- **Images:** pages load `.webp` from `static/`. The `og:image` swaps `.webp` for `.jpg` when a JPG copy exists, so a hero image should ship as both `.webp` and `.jpg`. With only a `.webp`, the preview falls back to the WebP.
- **Styles:** `assets/scss/style.scss` imports a trimmed Bootstrap (`_bootstrap-lite.scss`). Brand overrides are at the bottom of `style.scss`, and `$primary` is in `_bootstrap-variables.scss`. Sass is compiled with Dart Sass (set in `baseof.html`); Bootstrap's old-syntax deprecation warnings are silenced there on purpose.
- **Page URLs:** `[permalinks] pages = "/:filename/"` makes `content/pages/about/` serve at `/about/`.
